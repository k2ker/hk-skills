이 프로젝트를 기록 컨벤션 v2로 전면 이관하라. 먼저 hk `record` 스킬을 로드해 규칙을 확인하고, 시작 상태를 감지해 분기한다.

[상태 감지]
- **A. v1 컨벤션**: `MEMORY.md` + `docs/tech-notes/` (± `docs/DECISIONS.md`, `docs/memory/`, 완료 로그)
- **B. 제각각 문서**: 위 세트는 없지만 기록성 문서 존재 — NOTES/TODO/HISTORY/수기 CHANGELOG/산재된 docs/·README 속 기록성 절
- **C. 무**: 기록성 문서 없음 → `/hk:record:init` 절차만 수행하고 종료

[공통 원칙]
- **내용 손실 금지** — 지워지는 실질 내용은 조각에 있거나 정본 중복임이 확인돼야 한다. 애매하면 보존(조각화).
- **git 이력이 원본 보관소** — 단, **커밋된 것만**. 삭제 전 각 원본이 도달 가능한 커밋에 있는지 확인하고(`git log --oneline -1 -- <path>`), untracked·미커밋 파일은 내용을 조각에 전문 수록하거나 선커밋한 뒤에만 삭제한다. 복원법(`git show <ref>:<path>`)은 docs/log/README와 MEMORY 헤더에 명시.
- 규모가 크면(수십 KB+) 전담 에이전트에 위임하고 결과를 검수하라 — 구조 확인(MEMORY에 책갈피 섹션만 남았는지) + 조각 스팟 체크. **위임은 in-process 서브에이전트(Task/워크플로)로** — "워커는 기록 금지" 규약은 별도 세션 워커 얘기고, 이관 조각 생성의 오너는 어디까지나 migrate를 실행하는 이 세션(리드)이며 에이전트는 그 도구다. 검수 없이 에이전트 산출을 확정하지 마라.
- 작업 전 git 작업 트리가 더러우면 먼저 사용자에게 확인. **커밋은 하지 않는다**(사용자 승인 게이트).

[A. v1 전면 이관] — gamescom record-pilot 실증 방식
1. init의 **scaffold 절차**(preflight 제외, 1~4단계)로 뼈대 생성
2. **닫힌 서사**(tech-notes·완료 로그·MEMORY의 완료 항목·교훈 모음) → `docs/log/` 날짜 조각으로. 작업 단위로 묶고(줄 단위 조각화 금지), 날짜는 그 항목 자체의 날짜, frontmatter `refs`에 원 tech-note 번호·D번호·커밋
3. **열린 것** → MEMORY 미결에 3줄 이내(상태·블로커·포인터) / **유효 계약·함정** → MEMORY 한시 계약(항구적이면 CLAUDE.md 승격 제안)
4. **정본 중복**(CLAUDE.md·코드 주석·specs가 이미 기록) → 삭제, 필요 시 포인터 한 줄
5. **레거시 삭제** — tech-notes/·완료 로그·archive성 기록. 🔇 리마인드 금지 류 표기는 표기와 함께 보존
6. 검증·보고: MEMORY 최종 크기, 생성 조각 수, 보존 우선 처리 목록, 삭제한 정본 중복 목록

[B. 제각각 문서 재구성]
1. init의 **scaffold 절차**(preflight 제외, 1~4단계)로 뼈대 생성
2. **발굴**: 기록성 내용 스캔 — NOTES/TODO/HISTORY/수기 CHANGELOG/산재 문서/README의 기록성 절 (코드·설정·스펙 문서는 대상 아님)
3. **분류**: 열린 것→MEMORY 미결 / 사실·경위·교훈→조각(날짜는 원문 기준 추정, 불명이면 오늘 날짜 + refs에 출처 명시) / 결정→DECISIONS / 항구 규칙→CLAUDE.md 승격 제안
4. **원본 처리**: 기록성 내용만 담던 파일은 삭제, 혼합 문서(README 등)는 기록성 절만 제거 — 전부 diff로 보고
5. 검증·보고는 A와 동일
