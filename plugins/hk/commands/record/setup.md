이 프로젝트에 기록 컨벤션을 적용하라. 먼저 hk `record` 스킬을 로드해 규칙을 확인한다. 템플릿 원본은 `${CLAUDE_PLUGIN_ROOT}/templates/` (환경변수로만 참조 — 캐시 경로는 버전마다 바뀐다).

## 0. 상태 판정 (쓰기 전에)

`docs/log/` 존재 여부 **하나로만** 판정한다:

- **있음 = 이미 활성.** → **§A 보충 모드**(비파괴). 조각은 절대 재처리하지 않는다.
- **없음** → **§B 적용 모드.**

## §A 보충 모드 (재실행 안전 — 기존 것을 고치거나 지우지 않는다)

1. 빠진 뼈대만 채운다: `docs/log/README.md`, `MEMORY.md`(없을 때만), CLAUDE.md 컨벤션 문단(없을 때만).
2. `MEMORY.md`에 없는 섹션을 **추가만** 한다(기존 내용 보존·재배치 금지) — 미결 / 사용자·작업 방식 / 제약·함정 / 참조 / 인덱스.
3. **미이관 잔여를 보고만 한다.** 기록성 문서(`docs/tech-notes/`·`docs/memory/`·archive성 기록·NOTES/TODO/HISTORY·수기 CHANGELOG 등)가 남아 있으면 목록·규모를 보고하고 **"마저 이관할까?"를 묻는다.** 승인 없이는 아무것도 옮기거나 지우지 않는다. 승인하면 §B 3~5단계를 그 잔여에만 적용한다.
4. 결과 보고: 추가한 것 / 이미 있어 건너뛴 것 / 미이관 잔여.

## §B 적용 모드

**1. 발굴** — 기록성 문서를 전부 찾는다. 고정 목록이 아니라 **"코드·설정·스펙이 아닌, 지나간 작업·결정·교훈·상태를 적어둔 문서"면 대상**이다. 흔한 위치(예시일 뿐): `MEMORY.md`, `docs/tech-notes/`, `docs/memory/`, `docs/DECISIONS.md`, `docs/adr/`, `NOTES.md`, `TODO.md`, `HISTORY.md`, 수기 CHANGELOG, `docs/` 산재 문서, README의 기록성 절. **0건이면 2단계만 하고 종료**(신규 프로젝트).

**2. 뼈대** — `docs/log/` + `templates/log-readme.md`→`docs/log/README.md`, `templates/memory-skeleton.md`→`MEMORY.md`(없을 때만), CLAUDE.md에 `templates/claude-md-snippet.md` append(같은 섹션 있으면 스킵). `docs/DECISIONS.md`는 **선택** — 이미 있거나 D번호 참조 체계를 쓰는 프로젝트만 유지·생성한다(기본은 결정도 조각 `type: decision`).

**3. 분류** — 발굴한 내용을 성격별로:
- 아직 열린 것(미해결·대기·진행 중) → `MEMORY.md` 미결, 항목 3줄 이내
- 지금도 참인 계약·함정·제약 → `MEMORY.md` 해당 섹션 (여러 세션 살아남을 항구 규칙은 CLAUDE.md 승격 제안)
- 사용자·작업 방식(선호·교정) → `MEMORY.md` 해당 섹션
- 끝난 일의 사실·경위·교훈 → `docs/log/YYYY-MM-DD-주제.md` 조각(작업 단위로 묶기, 줄 단위 조각화 금지). 날짜는 원문 기준, 불명이면 오늘 날짜 + `refs`에 출처
- 결정 → DECISIONS 유지 프로젝트면 거기, 아니면 조각 `type: decision`
- 다른 정본(코드·CLAUDE.md·specs·git)이 이미 갖는 내용 → 옮기지 않는다

**4. 원본 정리** — 이관 완료분 삭제. **단 커밋된 것만** — `git log --oneline -1 -- <path>`로 확인하고, untracked·미커밋이면 조각에 전문을 담거나 선커밋 후 삭제. 혼합 문서(README 등)는 기록성 절만 제거. 복원법(`git show <ref>:<path>`)을 `docs/log/README.md`·MEMORY 헤더에 명시.

**5. 검증·보고** — MEMORY 구조(섹션만 남았는지)·조각 스팟 체크. 보고: 생성 조각 수, MEMORY 크기 변화, 삭제 목록, 보존 우선 처리한 애매 항목.

## 공통

- **작업 트리가 더러우면 먼저 확인**하고, **커밋하지 않는다**(사용자 승인 게이트).
- 규모가 크면(수십 KB+) in-process 서브에이전트에 위임하고 결과를 검수한다 — 이관의 오너는 이 세션(리드)이고 에이전트는 도구다. 별도 세션 워커에게 시키지 마라(기록 금지 규약과 충돌).
- **내용 손실 금지** — 애매하면 조각으로 보존.
