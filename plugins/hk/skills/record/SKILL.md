# 기록 컨벤션 v2 — 조각 로그 + 책갈피

목적: 어느 PC·어느 세션이 와도 프로젝트의 히스토리("무슨 일이 있었나")와 현재 위치("뭘 하다 멈췄나")를 싸게 복원한다. 병렬 세션·워크트리에서 충돌 없이. 기록이 작업의 병목이 되면 안 된다.

## 구조 (프로젝트 안)

| 파일 | 역할 | 쓰는 순간 |
|---|---|---|
| `docs/log/YYYY-MM-DD-주제.md` | **조각** — 일단락의 박제 기록 | 일단락마다 1개 |
| `MEMORY.md` | **책갈피** — 열린 일·한시 계약만, 항목 3줄 이내 | 미결이 생기거나 닫힐 때 |
| `docs/DECISIONS.md` | **결정 원장** — 항목 3줄 상한, 증거는 조각 링크 | 결정이 났을 때만 |
| `CLAUDE.md` | **항구 규칙** — 여러 세션을 살아남는 계약의 승격지 | 가끔, 승인 후 |

새 세션의 동선: MEMORY.md(책갈피)를 읽고 시작 → 맥락이 더 필요하면 `ls docs/log/`(연대기)를 거슬러 읽는다.

## 라우팅 — 기록할 때 묻는 질문 3개

1. **뭘 알아냈나/했나** → `docs/log/` 조각
2. **뭘 정했나** → DECISIONS (3줄 상한)
3. **뭘 하다 말았나** → MEMORY 미결

## 조각 규칙

- 파일명 `YYYY-MM-DD-주제슬러그.md` — **순번 금지**(병렬 세션 간 번호 경쟁·머지 충돌 원천 차단). 같은 날 같은 슬러그가 겹칠 드문 경우만 브랜치명 접미.
- frontmatter: `date`, `type: note|lesson|incident`, `refs: [...]` (D번호·커밋·관련 조각·뒤집는 조각).
- **박제** — 과거 조각의 본문은 고치거나 지우지 않는다. 내용이 뒤집히면 **새 조각 + refs에 옛 조각**(전방 링크 의무). 옛 조각 상단의 `> ⚠️ 구판` 도장은 선택(위험도 높은 것만).
- **후속절 append는 박제의 유일한 예외** — 같은 주제가 이어지면 **그 조각의 오너만** 하단에 후속절을 덧붙일 수 있다(기존 본문 수정은 여전히 금지). 남의 조각엔 새 조각 + refs (병렬 세션이 같은 파일을 고치면 충돌).
- **"지금 뭐가 맞나"는 조각에서 읽지 않는다** — 현재 상태의 정본은 MEMORY·CLAUDE.md·DECISIONS뿐.

## 필터 — 쓰기 전에

- **정본 중복 금지**: 코드·git·DECISIONS·전용 장부가 이미 기록하는 내용은 쓰지 않는다. 코드·git으로 알 수 없는 것(경위·실측·교훈·철회된 제안)만.
- **한 곳에만** — 같은 내용은 한 집에, 나머지는 링크.
- **trivial 면제** — 오타·사소한 설정·대화뿐인 턴은 조각을 만들지 않는다. **훅 통과용 서사 금지** — 쓸 사실·결정·교훈이 없으면 쓰지 않는다.
- **승격** — MEMORY의 계약·함정이 여러 세션을 살아남아 항구화되면 CLAUDE.md로 승격을 제안한다(승인 후 이동).

## 병렬·위임 — 단일 기록자 (오케스트레이터 중립 규약)

- **병렬 워커는 기록하지 않는다.** 산출·발견은 보고(worker_done 등)로 리드에게 넘기고, 기록은 **리드가 랜딩 때 1회** 수행한다. 워커 N명이 돌아도 기록 파일을 만지는 손은 하나 — 충돌이 구조적으로 없다.
- **워커 마커**: 워커를 프로비저닝하는 주체(Orca·수동 worktree·기타 오케스트레이터 누구든)가 `touch "$(git -C <워커경로> rev-parse --absolute-git-dir)/hk-worker"` — **반드시 `--absolute-git-dir`**(상대 경로는 실행 셸 cwd 기준으로 풀려 엉뚱한 repo에 마커를 심는 실측 사고가 있다). **git 메타데이터에 두므로 커밋에 섞일 수 없고** 워크트리 제거와 함께 사라진다. Stop 게이트가 1ms에 감지해 면제. 작업 트리 파일 마커는 커밋 오염 경로가 있어 지원하지 않는다(이 컨벤션은 git 전제). 규약의 소속은 record 컨벤션이며 특정 오케스트레이터에 종속되지 않는다.
- 마커가 없는 비정형 위임은 게이트 최종 단(LLM 판정)의 위임 문맥 판단이 백업.

## 조회

- 연대기 = `ls docs/log/` (파일명 정렬이 곧 시간순) · 유형별 = frontmatter grep (`grep -l "type: lesson" docs/log/*.md`)
- 이관 전 옛 체계(tech-notes NNN 등)의 참조 = git 이력 (`git show <ref>:docs/tech-notes/…`)

## 명령

- `/hk:record:init` — 새 프로젝트에 구조 깔기 (멱등, opt-in은 사람이 결정)
- `/hk:record:migrate` — 기존 프로젝트 전면 이관 (v1 컨벤션 / 제각각 문서 / 무 — 상태 감지)
