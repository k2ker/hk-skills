# git 동기화 가드 (2026-08-24 구현 → 09-08 간결화)

원격이 앞서 있는데 모르고 미는 사고를 막는 PreToolUse(Bash) 훅. **미커밋 — 커밋 승인 대기.**

## 동작

- `git push` → 목적지(`@{push}`, 없으면 upstream)가 앞서 있으면 **차단** + 새 커밋 3개 목록
- `git commit` → **알려만 주고 통과**
- 무슨 문제든(오프라인·인증 프롬프트·판별 불가·비-git) **전부 통과**(fail-open)

파일: `plugins/hk/hooks/git-sync-guard.sh` **98줄** + 테스트 `hooks/tests/git-sync-guard.test.sh` **11케이스 GREEN**.

## 설계 결정 — 왜 commit이 아니라 push를 막나

1. 뒤처진 상태의 커밋은 git에서 **정상**이고, 뒤처진 상태의 push는 **실제로 거부**된다. 가드는 실제 실패 지점에 건다.
2. 커밋을 막으면 **더러운 작업 트리에서 통합을 강요**하게 되고, 그게 꼬이면 돌아갈 세이브포인트가 없다. "커밋 먼저 → 통합"이 안전하다.
3. 커밋은 잦고 push는 드물다.

단 "더 일찍 알자"는 요구를 반영해 **commit 시점에도 fetch해서 알림**은 준다(차단 없이).

## 간결화 (09-08)

Codex 리뷰 4라운드에서 나온 우회 방지 코드(삼각 워크플로 목적지 계산, `-c` 설정 보존, 다중 호출 전수 검사, force/lease 3분기, base64 plan 인코딩 등)로 204줄까지 불었던 것을 **98줄로 되돌렸다.** 근거: **이건 자물쇠가 아니라 안전벨트**다. 우회되면 그때 안 잡아주는 것뿐이고, 읽을 수 있는 코드가 더 값지다. 남긴 판별 규칙은 "git 뒤 전역 옵션을 건너뛴 첫 서브커맨드"뿐 — `git log --grep push` 오탐과 `git -C <경로> push` 미탐을 둘 다 막는 최소선이다.

## 함정 (재발 방지 — 전부 실측)

- **인용 인자 정규식**: raw JSON에 `git[^"]*push` 류를 쓰면 `git -C "경로" push`에서 끊겨 통째 우회. 리드가 워커 브랜치 밀 때 매일 쓰는 형태였다.
- **`@{push}`는 push.default=simple + 삼각 구성에서 해석 실패하지만 실제 push는 진행된다** — rev-parse 실패 ≠ push 실패.
- **bash `read`는 개행 없는 마지막 줄에서 실패를 반환** — 파이프 디코드 루프가 조용히 빈손이 된다(`|| [ -n "$var" ]` 가드 필요).
- **`--disallowedTools`는 가변 인자라 뒤따르는 위치 인자를 삼킨다** — 프롬프트는 stdin으로.
- **테스트에서 fetch를 막으면 원격 상태가 갱신되지 않아 전부 통과로 보인다** — 로컬 bare 원격은 그냥 fetch시키는 게 맞다.

## 교훈 — 리뷰 수렴

HIGH(인용 우회·명시 인자 무시)는 진짜 결함이었지만 후반 라운드는 우리 워크플로에 없는 적대적 엣지로 번졌고, 결국 사용자 지적으로 절반을 되돌렸다. **리뷰 루프에 수렴 기준이 없으면 리뷰어의 완벽 기준이 머지 기준이 된다** — 라운드 상한·HIGH 의무/MED 재량 같은 규칙이 필요하다(제안 상태).
